# Claude Code カスタマイズ機能の粒度と相互関係

## 1. 粒度の整理（影響範囲：大→小）

**重要**: この図は「影響範囲の大きさ」を表しており、包含関係ではありません。

```
┌─────────────────────────────────────────────────────────────────┐
│  CLAUDE.md（最大粒度）                                           │
│  ─────────────────────                                          │
│  プロジェクト全体の「憲法」                                       │
│  常にコンテキストに存在し、他のすべての機能の振る舞いを規定        │
│                                                                 │
│  ┌───────────────────────────────────────────────────────────┐ │
│  │  Rules（中〜大粒度）                                       │ │
│  │  ──────────────────                                       │ │
│  │  CLAUDE.mdの「条項」を分割したもの                         │ │
│  │  特定ファイルパターンにスコープを限定可能                   │ │
│  └───────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘

┌──────────────────────────────────────┐
│  Skills（中粒度）                    │
│  ────────────────                    │
│  専門知識・手順のパッケージ           │
│  必要に応じて動的にロード             │
│  複数のコンテキストで再利用可能       │
└──────────────────────────────────────┘
        ▲
        │ 読み込まれる（skills: フィールド）
        │
┌────────────────────┐  ┌────────────────────────┐
│ Subagents（小粒度）│  │ Custom Commands（小粒度）│
│ ─────────────────  │  │ ──────────────────────  │
│ 独立タスク実行者   │  │ 定型プロンプト          │
│ 隔離されたコンテ   │  │ ショートカット          │
│ キストで動作      │  │ Subagents/Skillsを呼出  │
└────────────────────┘  └────────────────────────┘
```

### 粒度の比較表

| 機能 | 粒度 | スコープ | ライフサイクル | 情報量 |
|------|------|----------|----------------|--------|
| **CLAUDE.md** | 最大 | プロジェクト全体 | 常時ロード | 数百〜数千トークン |
| **Rules** | 大〜中 | ファイルパターン別 | 常時または条件付きロード | 数十〜数百トークン/ファイル |
| **Skills** | 中 | タスク種別 | 必要時に動的ロード | 数百〜数千トークン |
| **Subagents** | 小 | 単一タスク | タスク実行時のみ | 独立コンテキスト |
| **Custom Commands** | 小 | 単一アクション | 呼び出し時のみ | 数十〜数百トークン |

## 2. 相互関係（使う/使われる関係）

### 関係図

```
                    ┌──────────────┐
                    │  CLAUDE.md   │
                    │  (方針)      │
                    └──────┬───────┘
                           │ 規定する
                           ▼
                    ┌──────────────┐
                    │    Rules     │
                    │ (CLAUDE.mdの │
                    │   分割版)    │
                    └──────┬───────┘
                           │ 参照される
           ┌───────────────┼───────────────┐
           │               │               │
           ▼               ▼               ▼
    ┌────────────┐  ┌────────────┐  ┌────────────┐
    │   Skills   │  │ Subagents  │  │  Commands  │
    │  (知識)     │  │ (実行者)    │  │(エントリ)   │
    └─────┬──────┘  └──────┬─────┘  └──────┬─────┘
          │                │               │
          │                │               │
          │                │               └───呼び出す──┐
          │                │                            │
          └────読み込まれる─┘                            │
                    │                                  │
                    │ skills: [skill-name]             │
                    ▼                                  ▼
            ┌────────────────┐              ┌────────────────┐
            │ Subagents が   │              │ Commands が    │
            │ Skills を      │              │ Subagents を   │
            │ コンテキストに  │              │ 呼び出す       │
            │ 読み込む       │              └────────────────┘
            └────────────────┘
                    │
                    │ Skills も Commands から
                    │ 直接参照・呼び出し可能
                    ▼
            ┌────────────────┐
            │ Commands が    │
            │ Skills を      │
            │ 明示的に参照   │
            └────────────────┘
```

### 詳細な関係性

#### (1) CLAUDE.md → 全機能

**CLAUDE.md は他のすべての機能の「上位規約」として機能**

```markdown
# CLAUDE.md の例

## Subagent の使い方
- コードレビューは必ず code-reviewer サブエージェントを使用
- テスト実行は test-runner サブエージェントに委譲

## Skills の使い方  
- PDF処理は pdf-skill を優先的に使用
- ドキュメント生成時は docx-skill を参照

## Commands の規約
- /deploy コマンド実行前は必ずテストを通すこと
```

#### (2) Rules ⊂ CLAUDE.md

**Rules は CLAUDE.md の「分割・特化版」**

- 同じ優先度だが、より細分化された指示
- CLAUDE.md が「憲法」なら、Rules は「条例」
- 両者は補完関係（矛盾する場合は明確な優先順位なし→設計で避ける）

```
CLAUDE.md: 「TypeScriptを使用、テストは必須」
  └── rules/api.md: 「APIは入力バリデーション必須」
  └── rules/frontend.md: 「コンポーネントはmemo化を検討」
  └── rules/testing.md: 「カバレッジ80%以上」
```

#### (3) Subagents → Skills（依存関係）

**Subagents は Skills を読み込んで使用可能**

Subagents は親の会話から Skills を自動継承しません。明示的に指定する必要があります。

```yaml
# .claude/agents/pdf-expert.md
---
name: pdf-expert
description: PDF処理の専門家
skills: pdf-processing, docx  # Skills の完全な内容がコンテキストに注入される
---
```

**重要な仕様（公式ドキュメントより）:**
- Subagents は Skills を自動継承しない
- `skills:` フィールドで指定された Skills の**完全な内容**が Subagent の起動時にコンテキストに注入される
- 単に「呼び出し可能」になるのではなく、Subagent のコンテキストの一部として統合される

この仕組みにより、Subagent は専門的な知識を持った状態で独立したタスクを実行できます。

#### (4) Custom Commands → Subagents

**Commands から Subagents を呼び出し可能**

```markdown
# .claude/commands/full-review.md
---
description: 完全なコードレビューを実行
---

以下の手順で完全なコードレビューを実行してください：

1. code-reviewer サブエージェントでコード品質をチェック
2. security-scanner サブエージェントでセキュリティ検査
3. 結果を統合してレポート作成
```

#### (5) Custom Commands → Skills

**Commands から Skills を明示的に呼び出し可能**

```markdown
# .claude/commands/create-report.md
---
description: レポートを作成
---

docx スキルを使用して、以下の形式でレポートを作成してください：
...
```

#### (6) Skills ↔ Skills（相互参照）

**Skills 間で参照関係を持つことが可能**

```yaml
# .claude/skills/report-generator/SKILL.md
---
name: report-generator
description: レポート生成
---

データ分析後、以下のスキルを組み合わせて出力：
- docx スキルで Word 文書を生成
- pdf スキルで PDF 形式でも出力
```

## 3. 依存関係のまとめ

### 「使う側」と「使われる側」の関係

| 使う側 | 使われる側 | 関係の説明 |
|--------|------------|------------|
| **CLAUDE.md** | Rules, Skills, Subagents, Commands | 全機能の振る舞いを規定（呼び出すのではなく方針を定める） |
| **Rules** | （なし） | 参照されるのみ |
| **Subagents** | **Skills** | `skills:` フィールドで明示的に読み込み（完全な内容が注入される） |
| **Commands** | Subagents, Skills | 呼び出し・参照可能（オーケストレーションのエントリーポイント） |
| **Skills** | 他のSkills | 相互参照可能（Skill内で他のSkillに言及） |

### 重要な制約（公式仕様）

| 機能 | 制約内容 |
|------|----------|
| **CLAUDE.md** | 他の機能を「呼び出す」ことはできない（方針を規定するのみ） |
| **Rules** | 他の機能を呼び出せない（静的な規約） |
| **Subagents** | • 他のSubagentsを直接生成できない（ネスト不可）<br>• Skills を自動継承しない（明示的な指定が必要） |
| **Skills** | • Subagentsを直接生成できない<br>• `context: fork` + `agent:` 指定で独立コンテキストでの実行は可能 |

## 4. 設計指針

### レイヤー構造として考える

```
┌─────────────────────────────────────────────────────┐
│          Layer 0: 方針・規約（常時適用）              │
│          CLAUDE.md + Rules                          │
│          → 「何をすべきか/すべきでないか」           │
├─────────────────────────────────────────────────────┤
│          Layer 1: 知識・手順（動的ロード）           │
│          Skills                                     │
│          → 「どうやるか（専門知識）」               │
├─────────────────────────────────────────────────────┤
│          Layer 2: 実行（タスク単位）                 │
│          Subagents + Commands                       │
│          → 「実際にやる」                           │
└─────────────────────────────────────────────────────┘
```

### 推奨される設計パターン

1. **CLAUDE.md は薄く保つ**
   - 具体的なルールは Rules に分離
   - オーケストレーション（どの機能をいつ使うか）に集中

2. **Rules はドメインごとに分離**
   - `paths` で適用範囲を限定
   - マージコンフリクトを減らす

3. **Skills は再利用可能な専門知識**
   - プロジェクト横断で使える形で設計
   - スクリプトと組み合わせて実行可能に

4. **Subagents は隔離が必要な処理に**
   - 大量出力（テスト結果、ログ分析）
   - 独立した判断が必要なタスク

5. **Commands は頻繁に使う操作のショートカット**
   - 複雑なワークフローは Skills + Subagents の組み合わせで
   - Commands はそれらを「呼び出す」エントリーポイント

## 5. 具体的な組み合わせ例

### 例: コードレビューワークフロー

```
[CLAUDE.md]
  「PRレビュー時は必ずcode-reviewerサブエージェントを使用」
      │
      ▼
[Commands: /review]
  「現在のPRをレビュー」
      │
      ├──呼び出し──▶ [Subagent: code-reviewer]
      │                    │
      │                    ├──読み込み──▶ [Skill: security-checklist]
      │                    └──読み込み──▶ [Skill: performance-guide]
      │
      └──参照──▶ [Rules: code-style.md]
                    「このプロジェクトのコードスタイル」
```

### 例: ドキュメント生成ワークフロー

```
[CLAUDE.md]
  「ドキュメントはブランドガイドラインに従う」
      │
      ▼
[Commands: /generate-doc]
  「仕様書を生成」
      │
      ├──読み込み──▶ [Skill: docx]
      │                 「Word文書の作成方法」
      │
      ├──読み込み──▶ [Skill: brand-guidelines]
      │                 「会社のブランドルール」
      │
      └──参照──▶ [Rules: documentation.md]
                    「このプロジェクトのドキュメント規約」
```
